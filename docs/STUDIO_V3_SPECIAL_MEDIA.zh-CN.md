# General Studio：特殊纸张、自定义尺寸与用户提供的打印能力

## 无代码设置与单一保存模型

在 Studio 的 **Global style → Paper & margins** 选择纸张、方向及页面边距，检查待应用设置，然后 **Apply style**。此功能面向一般 PrintForm Studio，不要求 ERPNext 或任何 ERP 连接。

预设来自共享的 `src/printform/paper-sizes.js`；Studio、预览分页、模板尺寸及 CSS 打印尺寸不维护另一份纸张表。原有 `paper` 字符串与 A4/A5/LETTER/LEGAL 保持兼容。可选的特殊介质都是有限页面：

| 选项 | 原始尺寸（mm，方向变换之前） |
| --- | --- |
| A4 | 210 × 297 |
| A5 | 148 × 210 |
| LETTER | 215.9 × 279.4 |
| LEGAL | 215.9 × 355.6 |
| RECEIPT_58 | 58 × 120 |
| RECEIPT_80 | 80 × 160 |
| LABEL_100_70 | 100 × 70 |
| LABEL_50_30 | 50 × 30 |
| CONTINUOUS_210_140 | 210 × 140 |
| FANFOLD_210_280 | 210 × 280 |
| CUSTOM | 用户明确输入宽、高；各 20–1000 mm，可含小数 |

A5 横向是同一 A5 预设的方向设置，不是重复纸张规格。`landscape` 只交换一次输入宽、高；长边未必成为高度，程序不再排序或修正尺寸。热敏纸、连续纸、折叠纸设置也不等于无限卷纸、自定义切刀指令或原生驱动支持。

**纸张尺寸单位为 mm，页面边距仍为 CSS px（96 px/in）。** 四边页面边距各 0–72 px；扣除后至少保留 48 px 内容宽及 24 px 内容高。自定义输入、越界值和矛盾声明均拒绝，不静默钳制。预览按实际分页内容验证；小纸张不会让任意六列表格自动变得可读。窄页面采用堆叠布局及较小内留白，不缩放字体或源数据。不能容纳的内容仍须调整字段、列、布局或纸张，再重新检查。

应用后的唯一源是 `manifest.studioV3.page`。`customSizeMm` 只存在于 CUSTOM；切回预设时移除。`spec.document`、模板分页属性及 `@page` 都由它编译。保存项目、重新打开、导出的自包含 HTML 都携带同一声明；Undo/Redo 一起恢复纸张及能力配置。导出的 HTML 用明确的 mm 页面尺寸；PDF 仍取决于浏览器实际执行 CSS 页面尺寸，不能据此认定硬件合格。

## 用户提供的打印能力配置

默认**没有**预选打印机、模拟打印机或“已认证”配置。展开 **User-supplied printer capabilities**，手工输入已知声明，或者导入本地 JSON；导入仅填入待应用表单，不直接改变项目。下载按钮导出本地 JSON 以供其他项目复用，不访问网络。

- 必须 `version: 1`、`source: "user-supplied"`，名称 1–100 字符。
- 可选最小/最大宽与高各 1–2000 mm，按**方向变换后的物理页面轴**比较；最小值不能大于最大值。
- 可选支持方向：portrait、landscape 或二者；空白表示未知。
- 可选四边不可打印留白各 0–100 mm，按已选方向的物理页面边缘定义；不是 CSS px。页面边距不足时拒绝 Apply，提示增大 px 边距或修正/移除配置。
- 可选 DPI 整数 72–9600 与切刀布尔声明**仅作资料**；DPI 不改变 96 CSS px/in，不控制设备、光栅化、切纸或驱动。
- 所有未知能力省略；未知不等于 0、false 或受支持。0 留白和 false 切刀保留原意。
- 取消勾选 **Use this user-supplied profile** 后 Apply 会移除当前配置，可 Undo；不改原生打印设置。

配置随项目和便携 HTML 保存。配置名称只是用户的文字，不是从操作系统查询到的设备身份，也不是打印测试的证据。配置验证通过仅表示输入互相一致，**不表示打印认证**。

## 验证与物理边界

浏览器质量报告继续以真实布局错误控制导出；纸张/能力声明矛盾会先在设计验证中拒绝。打印能力未知时允许检查、保存与导出浏览器文档，同时明确显示 `PHYSICAL_PRINTER_UNVERIFIED` 警告及 `physical.physicalBlocked: true`。该标记与浏览器 `ready` 独立，不能用浏览器 ready 替代实际硬件验收。

本次只读硬件可达性检查（2026-10-17）：`/usr/bin/lpstat -p -d` 返回退出码 1，输出 `No destinations added.` 和 `no system default destination`。当前没有配置的可用打印目标；没有发送作业、创建队列、修改驱动、纸张或系统设置。此结果不是所有网络/USB 环境均无硬件的证明，但当前没有可达目标供物理验收，因此保持 **physicalBlocked**。

新增的自动化入口：

- `tests/studio-v3-special-media.test.js`：共享预设、方向、mm/px、自定义上下界、配置矛盾、实际表单适配、保存重开与撤销恢复。
- `e2e/studio-v3-special-media.spec.js`：实际 Studio 控件选择所有预设和小数自定义尺寸；测量预览；保存/重开；网络禁用的自包含 HTML；Chromium 实际 PDF 字节、页数、页面尺寸与源文字检查；本地能力配置导入、导出、矛盾及恢复。

集成后真实三引擎运行 **36/36通过，0跳过、0重试**；覆盖10个有限预设与小数CUSTOM的控件、实测纸面、Save/Open、实际浏览器重开导出HTML、断网独立打开及打印媒体。Chromium实际产出11份PDF，按独立名义mm/96px/72pt尺寸与原始token校验，不从同一产品尺寸函数拷贝期望。[脱敏报告与PDF摘要](acceptance/STUDIO_V3_SPECIAL_MEDIA_20261017.json)。

首次组合浏览器运行30通过/36失败的报告与制品完整保留：30个有限纸张场景发现页内高度少约24px，另6个场景撞到Node环境没有DOMParser的测试调用。原生Chrome155独立诊断确认A4物理794×1123px，逻辑页1099px且页内margin-bottom24px；修复把屏幕分页间隔移到物理包装外，不修改纸张、边距、字体、数据或断言容差。修复后逻辑页1123px、页内间隔0、纸外间隔24，源token不变，零页面错误。HTML验收改为真实浏览器Open后Save，不注入DOMParser或伪造HTML解析；36项最终通过不覆盖先前失败。

仍未验证、也不自动声明：真实打印/走纸、设备裁切/不打印区域测量、切刀动作、驱动介质安装、DPI/色彩/热敏浓度、标签定位、条码扫描、多联纸/针式套打及无限连续卷纸。要解除物理阻塞，需实际可达且经授权的设备、选定介质和打印设置，再记录实体输出与测量；用户提供的能力表本身不能解除阻塞。
